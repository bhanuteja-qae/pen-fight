# pen-profiles — Wave-1 measurement harness (ticket #8)

Headless, deterministic measurement rig for the four pen-profile candidates.
Binding interface: `docs/prototypes/CONTRACTS-pen-profiles.md` (issue #8).
Wave 1 owns **only** these three files:

| File | Role |
|---|---|
| `profile_sweep.gd` | Sweep runner: one `SweepConfig` → per-shot rows + aggregate. Also the gate default run. |
| `noise_floor.gd` | Runs the baseline config over a fixed K=20 seed set; per-metric mean/stddev. |
| `README.md` | This document: how to run + the measured noise floor. |

`*.gd.uid` sidecars are auto-generated by Godot's import step (same as
`game/tests/*.gd.uid`); they are not authored content.

## How to run

Project root is `game/`. Every Godot invocation must be serialized behind the
shared lock.

```bash
cd ~/pen-fight/game
flock /tmp/pf-godot.lock -c 'DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 ~/godot/Godot_v4.7.2-stable_linux.x86_64 --headless --editor --quit --import .'
flock /tmp/pf-godot.lock -c 'DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 timeout 300 ~/godot/Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script res://prototypes/pen_profiles/noise_floor.gd'
flock /tmp/pf-godot.lock -c 'DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 timeout 600 ~/godot/Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script res://prototypes/pen_profiles/profile_sweep.gd'
```

Budget rule (contract): if a run would exceed its timeout, reduce `shots`,
never seeds. Headless physics runs at wall-clock 1x (measured: 600 physics
frames ≈ 10.0 s), so `noise_floor` at 4 shots/run × 20 seeds measured 186 s.

The default `profile_sweep.gd` run is the ticket's sample comparison:
`cobalt_control` (baseline) vs `graphite_anchor` (`mass = 1.4`), 12 shots, and
writes `user://pen_profiles_wave1_sweep.json`. `noise_floor.gd` writes
`user://pen_profiles_noise_floor.json`. Both are outside the repo, so Wave 1
creates no `results/` files. Wave 2 calls `ProfileSweep.run(cfg)` and
`ProfileSweep.write_json(result, path)` for each sweep and owns `results/*.json`.

## Harness design

- **World is built in code**, no production scene: a `PenBody` with a
  `CollisionShape2D` (CapsuleShape2D `radius 5.0`, `height 180.0`, child rotated
  90° so the barrel lies along local +X) and a sibling `Node2D` named `Table`
  carrying a `RectangleShape2D` sized `1180×640`, so production OOB geometry
  resolves (`pen_body.gd` `_any_part_outside`, radius + 8 px tolerance).
- **Profile levers are applied only as `RigidBody2D` runtime properties**:
  `mass`, `linear_damp`, `angular_damp`. No size change, no production edit.
  Baseline mirrors `main.tscn`: `mass 1.0`, `linear_damp 2.0`, `angular_damp 1.5`.
  (Godot combines these with the 2D default damping, giving the shipped ~2.1
  effective linear damp.)
- **Shots go through the production path** `pen.apply_flick(dir, power,
  contact_offset)` with `power` a 0..1 fraction (`MAX_IMPULSE = 1600.0` scales it
  inside) and `contact_offset` a fraction of half-length.
- **Seeded, fixed shot pattern**: `RandomNumberGenerator` with `config.seed`
  draws, in a fixed order, the angle jitter, then power, then grip offset. The
  direction fan is `20° ± 15°` with `± 6°` jitter, power `0.4..1.0`, offset
  `-1..1`. Launch is a single lane from `(-420, 0)` along +X (production has no
  walls), so the profile signal is read against a long run-out rather than the
  short table axis. Identical seed → identical shots for every profile.
- **Flight termination** replicates production: OOB (`_oob_emitted`), or
  linear `< 6.0 px/s` **and** angular `< 0.4 rad/s` for `0.25 s`
  (`PenBody.SETTLE_*`), or the 8 s `MAX_FLIGHT_FRAMES` cap (production in-flight
  backstop). A capped shot is recorded with `term = "timeout"`, never dropped.

## Metric definitions (fixed contract keys)

| Key | Meaning |
|---|---|
| `travel_px` | Total path length of the pen centre of mass, launch → termination (px). |
| `peak_speed` | Max linear speed sampled over flight (px/s). Resolves to the launch speed `J/m = power·1600/mass`; for `mass 1.0` it therefore equals `contact_impulse`. |
| `settle_time_s` | Physics seconds from impulse to termination. For a self-OOB shot this is time-to-OOB (`self_oob` disambiguates). |
| `contact_impulse` | Magnitude of the grip impulse queued by the production path: `power · PenBody.MAX_IMPULSE`. In this isolated single-pen rig (no pen-vs-pen contact) it measures the **commanded input impulse**, and is profile-invariant by construction — the fairness control, not a collision measurement. |
| `angular_travel_deg` | Total angular distance spun: `∫ |ω| dt`, in degrees. |
| `dispersion_deg` | Smallest angle (0..90°) between the pen's long axis at rest and its net travel direction — grip/skew scatter. |
| `self_oob` | Bool: production geometric OOB fired. |
| `self_oob_rate` | Aggregate fraction of shots that went OOB. |
| `dispersion_deg_p50`, `travel_px_p50` | Aggregate medians (other `*_p50` and a `mean` block are extras). |

## Measured noise floor (Wave 1 yardstick)

Baseline `cobalt_control` (`mass 1.0`, `linear_damp 2.0`, `angular_damp 1.5`),
`shots_per_run = 4`, K = 20 fixed seeds `1..20`. Per-run metric level across the
K runs; sample stddev (`n-1`).

| metric | mean | stddev | min | max |
|---|---:|---:|---:|---:|
| `travel_px` | 482.9916 | 50.3841 | 402.7825 | 592.2876 |
| `peak_speed` | 1115.3931 | 128.3509 | 879.9793 | 1376.8570 |
| `settle_time_s` | 2.3277 | 0.3245 | 1.7875 | 2.7792 |
| `contact_impulse` | 1115.3931 | 128.3509 | 879.9793 | 1376.8570 |
| `angular_travel_deg` | 129.5041 | 49.4046 | 67.7484 | 226.0817 |
| `dispersion_deg` | 38.8907 | 12.5460 | 21.5231 | 61.5358 |
| `self_oob_rate` | 0.1875 | 0.1791 | 0.0000 | 0.5000 |
| `timed_out_rate` | 0.0000 | 0.0000 | 0.0000 | 0.0000 |

Raw file: `user://pen_profiles_noise_floor.json`.

**What this is, honestly.** This is a **seed-sampling floor**, not solver
nondeterminism. Re-running the same `SweepConfig` is byte-identical (verified:
two `profile_sweep.gd` runs produced identical 12013-byte JSON), so the engine
contributes zero observed run-to-run noise here. The stddevs above are the
spread you get by changing the *shot sample* (seed). Wave 2 should therefore
compare profile arms **at the same seed** and treat an effect as "measured" only
when it exceeds the relevant per-metric stddev above; an arm-to-arm difference
smaller than that is within the sampling floor.

`timed_out_rate` is 0 for the baseline; a non-zero value in a Wave-2 arm means
that profile never settles inside the 8 s cap and its timing metrics are
censored, not measured.

## Sample sweep (gate output)

Seed 8, 12 shots, baseline vs `mass = 1.4`:

```
cobalt_control  mass=1.000 | travel_p50=536.7 peak_p50=1206.2 settle_p50=2.508 spin_p50=107.4 disp_p50=36.93 oob_rate=0.333 timeout_rate=0.000
graphite_anchor mass=1.400 | travel_p50=394.3 peak_p50= 861.6 settle_p50=2.592 spin_p50= 77.9 disp_p50=68.62 oob_rate=0.000 timeout_rate=0.000
```

`contact_p50 = 1206.2` is identical across both arms (same seeded input), as
intended. The mass arm moves travel and launch speed well outside the floor
above; this single 12-shot sample is evidence of a real lever, not proof of the
final range — that is Wave 2's job.

## Known limits / open uncertainty

- Single pen, no pen-vs-pen contact: `contact_impulse` is the commanded grip
  impulse, and `dispersion_deg` cannot capture collision deflection. A two-pen
  contact rig would be a new contract.
- The +X launch lane and power/offset ranges are a deliberate measurement choice
  (fixed, documented, seeded), not a human input model.
- No human has played these values; the floor says how reproducible the rig is,
  not whether any profile reads as fair or fun.
