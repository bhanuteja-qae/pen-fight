## 0. CORRECTION — the classroom-floor fix below never actually landed

Written after the fact. **Read this before trusting §1's classroom-floor claims.**

`8f0c993` claimed the bleed ring was repainted as linoleum with "zero near-black
pixels remain". It was not. Measured on the shipped asset: **400,634 px (33% of
`table_classroom.png`) were still the original near-black void** `(15,11,9)` in a
1-pixel lattice — only the even-x/even-y quarter of the ring was ever repainted.

**Root cause** (old generator, at the time only in `/tmp/gen_table_classroom.py`):
1. the "ensure nothing stays void-black" sweep iterated `range(0,H,2)` /
   `range(0,W,2)`, so 3 of every 4 ring pixels were never touched;
2. the per-tile tone variation used a stride-2 x loop.
Its *verification* sampled `range(0,H,4)`/`range(0,W,4)` — the same even lattice —
so it counted 0 near-black pixels on an asset that was one-third near-black.

**The vision model was right and got overruled.** The "dark almost black" floor it
reported was the black lattice; the "pixel truth is the object evidence" rebuttal
sampled the 25% of pixels that had been repainted. Earlier frames
(`/tmp/pf_classroom_floor.png`) were affected identically, so every classroom-floor
verification in this project to date was made on that lattice.

**Fix:** `game/assets/generate_classroom_floor.py` (now committed — the bug survived
only because the generator lived in `/tmp`) regenerates both classroom textures:
full-coverage tiles, desk rect `(160,120)-(1280,720)` bit-exact, ±14px feather.
Verified at **full resolution** (no subsampling): ring 537,600 px, 0 near-black,
0 desk-interior pixels altered. Render truth: void-colour pixels 105,825 → **0**,
ring-band mean brightness 32.5 → **103.9**, desk unchanged.

**Lesson for the next session (applies to every texture/visual claim):** a 1-pixel
lattice aliases perfectly against any even sampling stride. Never verify a texture
or a render by sampling every Nth pixel; scan every pixel (or use an area/box
downscale for looks — never point sampling).

## 3. How to run gates

```bash
# import (cwd MUST be game/; run twice; wipe .godot/exported after scene edits)
cd ~/pen-fight/game
DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 ~/godot/Godot_v4.7.2-stable_linux.x86_64 --headless --editor --quit --import .
# unit suites (any test):
DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 timeout 120 ~/godot/Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script res://tests/<name>.gd
# live render (Xvfb :99 must be up):
DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 PENFIGHT_AUTOPLAY=1 ~/godot/Godot_v4.7.2-stable_linux.x86_64 --path .
ffmpeg -y -loglevel error -f x11grab -video_size 1280x720 -i :99 -frames:v 1 /tmp/frame.png
```

**Critical gotchas (learned the hard way):**
- **Stale `.godot/exported` cache:** after editing scene textures, the running game can keep serving the old compiled scene — delete `.godot/exported` + kill/relaunch the game process before trusting a recapture. Pixel-truth (corners of the frame) is the only reliable verification; the vision model misreads cool-tinted grays as "black" (flags amber as "red", floor as "void").
- `apply_impulse` position arg = **offset vector in body basis** (no translation) — probe-measured, `torque_arm_probe.gd` locks it.
- Human power fraction only — never pass raw magnitudes into `apply_flick` (double-scaling → 2.56M impulse eject).
- `PackedVector2Array()` — `PackedVector2Array.new()` is invalid in 4.7.
- `clear_buffer()` hard-fails on an *active* generator — stop first.
- Display names **Amber/Cobalt**, never Red/Blue (matches art, CVD-safe).

## 4b. Pen art (2026-09-14, later session)

Four designs — **amber, cobalt, graphite, ivory** — all authored at 180×10 on
screen, i.e. exactly on the physics capsule (verified per instance by
differencing an in-game frame against a pens-hidden reference:
`game/tests/skin_shot.gd` + `8/8 instances 180x10, error +0x+0`).

Before this, no skin matched its own collision: the scene's 0.408 sprite scale
drew the default pair at 143×11 and the v4 skins at 109×21 onto a 180×10
capsule, and `set_pen_skin()` swapped only the texture, so choosing a skin
silently resized the pen. Scale is now applied by `set_pen_skin()` from
`PEN_SPRITE_SCALE`.

**A shadow that never rendered:** the pen shadows were at `z_index -1` under a
table sprite at `z_index 0`, so the desk texture drew over them — in every
version of the game (measured: pixels below a pen were byte-identical to bare
wood). Fixed by the layer order above.

**Honest status:** the art is procedurally rendered (no photographic source), and
the vision model's read on it at 1:1 oscillates — one pass returned "yes, real
pen" for all four, the next returned "no" for all four on near-identical art.
Treat the model as a defect FINDER (it caught real problems: banding, the
non-wrapping clip, the hard shadow stripe, the missing shadow) and not as a
pass/fail oracle. The remaining call is the eye of whoever is holding the phone.
